## Tooling note

This run's `tools/run_monitor.py` initially failed on the sitemap-index fetch with a `curl_cffi` SSL/connection-reset error. Root cause: `fetch_xml()` used `impersonate="chrome"` without pointing `curl_cffi` at the proxy's CA bundle (`/root/.ccr/ca-bundle.crt`, exposed via `SSL_CERT_FILE`/`REQUESTS_CA_BUNDLE`), unlike `tools/html_to_md.py`, which already does this correctly for page fetches. Fixed `fetch_xml()` to match `html_to_md.py`'s approach (`impersonate="chrome110"`, explicit `verify=` CA bundle) and the run succeeded on retry. Separately, `sanitize_filename()` was building sub-sitemap filenames from the full URL (producing `https___openai.com_sitemap.xml_<section>.xml`) instead of just the path (the established `sitemap.xml_<section>.xml` convention used by every prior run's tracked files) — fixed to use `urlsplit(url).path` and renamed this run's already-written files to match, avoiding a one-time mass file rename in git history. Both fixes are committed alongside this run's data so future scheduled runs use the corrected script.
